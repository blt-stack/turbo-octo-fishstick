# Pre-Purchase Questions — Reply Patterns + Action Recommendations

The highest-conversion category. The customer hasn't bought yet — they're seriously considering it. A fast, helpful reply often closes the sale; a slow or templated reply loses it.

Distinct tone from other CS categories: less apologetic (nothing to apologize for), more helpful, more sales-aware (the brand has a reason to be enthusiastic about its own product, within reason).

## Sub-types and how to identify them

| Sub-type | Identifier signals |
|---|---|
| **Sizing question (apparel, accessories)** | "What size should I get if I'm [measurement]"; "do you have a size chart" |
| **Materials / ingredients** | "What is this made of"; "is it [vegan/organic/non-toxic]"; "any allergens" |
| **Fit / compatibility** | "Does this work with [X]"; "is this compatible with [my setup]" |
| **Use-case / how-it-works** | "Can I use this for [purpose]"; "how does the [feature] work" |
| **Shipping speed** | "When will it arrive if I order today"; "do you ship to [country]"; "how fast" |
| **Stock / availability** | "Is [color/size] back in stock yet"; "when will more be available" |
| **Bundle / customization** | "Can I get a custom [thing]"; "do you offer [variant]" |

## Per-sub-type reply patterns + action recommendations

### Sizing question (apparel)

**Reply pattern:**
```
Hi [name],

Happy to help with sizing. Quick questions:

[Specific info request]
- What's your typical size in [comparable brand]?
- Are you looking for a [fitted/relaxed/oversized] feel?
- Height + weight if you're comfortable sharing (helps a lot for fit
  recommendations — totally optional)

[Direct CTA]
With that, I can point you to the size that'll work best. Or if you'd rather
just take a swing, our return policy is [N] days for unworn items, so the
downside of guessing wrong is small.

— [Founder name]
```

**Recommended actions:**
- No action — pre-purchase, no order yet
- Encourage the conversation (don't make them work too hard for the answer)
- If size chart is comprehensive, link directly + offer 1-on-1 if they want
- For high-AOV apparel: offer free returns for first-order sizing experiments

### Materials / ingredients

**Reply pattern:**
```
Hi [name],

[Direct answer]
Yes — [product] is made of [materials]. Specifically:

- [Material 1]: [source, certification if applicable]
- [Material 2]: [source]
- [Material 3]: [if relevant]

[Allergen / claim context]
[If asked: "no [allergen]"; "[organic/fair-trade/etc.] certified"; "[non-toxic
finishes]"]

[Brief brand context]
[One line about why these materials matter to the brand — earns the customer
who cares about materials]

— [Founder name]
```

**Recommended actions:**
- No action needed
- Be 100% accurate — material misrepresentation kills trust + creates legal liability
- For sensitive claims (organic, non-toxic, vegan, allergen-free): only state what's provably true. "We don't use [X]" is safer than "totally [Y]-free" unless verified.

### Fit / compatibility

**Reply pattern:**
```
Hi [name],

Quick answer: [yes/no/depends].

[If yes:] [Product] works with [their setup] — here's how: [brief explanation].

[If no:] [Product] doesn't fit [their setup] because [reason]. What might
work for you instead is [alternative if you have one] or [point to a
relevant collection].

[If depends:] [Product] works with [their setup] if [condition]. If you can
confirm [specific spec], I can give you a definitive yes or no.

— [Founder name]
```

**Recommended actions:**
- No action — sales-aware reply
- Be direct (don't hedge if you know the answer)
- If you recommend an alternative product, do it briefly — don't oversell

### Use-case / how-it-works

**Reply pattern:**
```
Hi [name],

[Direct answer to the use case question]
Yes/maybe/no, with the reasoning.

[Specific guidance]
For your specific use case ([their use case]), here's what works best:
1) [Step or recommendation]
2) [Another consideration]

[Resource pointer if useful]
We have a [brewing guide / setup tutorial / FAQ page] at [link] that goes
deeper if you want it.

[Soft close]
Let me know if that lands.

— [Founder name]
```

**Recommended actions:**
- No action needed
- Point to existing resources where they exist (saves the customer time)
- Don't push the sale — answer the question first; the sale follows trust

### Shipping speed / international

**Reply pattern:**
```
Hi [name],

If you order today, [product] ships within [X business days] and arrives in
[Y-Z business days] via [standard / expedited]. So roughly [date].

If you need it faster, we offer [expedited] which gets it there in [N days]
for [$cost].

[International, if asked:]
We do ship to [country]. Total shipping time is roughly [X-Y business days].
Duties / VAT depending on your country are typically calculated at checkout —
[brief note on whether they're prepaid or due on delivery].

— [Founder name]
```

**Recommended actions:**
- No action — info reply
- Be conservative on shipping time estimates (under-promise, over-deliver)
- For international: be honest about duties — surprise duties are a top complaint category

### Stock / availability

**Reply pattern:**
```
Hi [name],

[Color/size] in [product] is currently sold out. We're expecting a restock
in [N weeks] — typically [date range].

If you'd like, I can add you to the waitlist — you'll get an email the moment
it's back in stock, before we announce publicly. Want me to set that up?

— [Founder name]
```

**Recommended actions:**
- Add to back-in-stock waitlist (which triggers skill #7's Back-in-Stock flow when relevant)
- If restock timeline is uncertain, say so honestly ("not sure yet — likely 4-6 weeks")
- Never give a restock date you can't hit — sets up a second angry ticket

### Bundle / customization

**Reply pattern:**
```
Hi [name],

[If standard bundles exist:]
We don't have a pre-built bundle for that, but I can create a custom one for
you. The pieces you'd want are:
- [Product 1] at [$price]
- [Product 2] at [$price]
- [Product 3] at [$price]

I can offer a 10% bundle discount if you want all three: total $[X].

[If customization is possible:]
We do some customization on [product] — [specifics]. Custom pieces take
[N weeks] additional production time.

[If neither:]
We don't currently offer [custom thing], but I'll flag it internally — this
isn't the first time we've heard the request.

— [Founder name]
```

**Recommended actions:**
- For bundle requests within scope: offer the bundle + small bundle discount
- For customization requests not currently offered: note internally if the request comes up repeatedly
- Don't promise customization the brand can't actually deliver

## Sentiment overrides for pre-purchase

Pre-purchase skews positive — the customer is interested. Sentiment matters less here. The main tone variation:

| Sentiment | Adjustments |
|---|---|
| Curious / friendly | Match warmth, slightly more conversational |
| Neutral / transactional | Standard pattern works; respect their efficiency |
| Skeptical / comparison-shopping | Be specific, share proof points, don't oversell |

---

## Common pitfalls in pre-purchase replies

- **Treating like a transaction instead of a relationship start** — pre-purchase customers who get a warm helpful reply become lifetime customers more often than those who get a short rushed reply
- **Hard-selling the answer** — answer the question they asked first; don't pivot to a different product unless they're a poor fit for the asked-about one
- **Generic "check our FAQ"** without the specific answer — wastes time, signals laziness
- **Slow turnaround** — pre-purchase questions go cold fast; reply within 4 hours when possible
- **Templated openers** ("Thank you for your interest in our brand!") — sounds AI-generated even when it isn't
- **Missing the obvious upsell when it's natural** — if customer asks about a pour-over, the brewing guide bundle is a fair mention; not pushing it sometimes loses the natural opportunity

---

## Pre-purchase as the highest-leverage CS work

Most CS-cost tracking treats pre-purchase questions as a "cost center" (time spent without a guaranteed sale). That's wrong. Pre-purchase replies often have 30-60% conversion rates (customer asks, brand replies, customer buys). The cost-per-conversion is far lower than ads.

The skill's bulk-mode .xlsx Sheet 2 (Category Breakdown) shows pre-purchase volume — a healthy DTC business with smart marketing should see 30-50% of CS volume in pre-purchase. Lower than that means the brand isn't surfacing well or isn't trusted yet.

---

## No systemic-issue patterns to flag

Unlike shipping / defects / returns, pre-purchase doesn't usually surface systemic issues to fix (other than: "we should write this answer into the FAQ since 8 customers asked it this month"). The skill's batch mode Sheet 3 for pre-purchase recommends:

- **FAQ additions:** questions asked 3+ times across the batch → recommend adding the question + answer to the brand's public FAQ
- **Product page additions:** questions about specific products that the product page should be answering → flag the page for improvement (and recommend running skill #1 or skill #3 to refresh)
