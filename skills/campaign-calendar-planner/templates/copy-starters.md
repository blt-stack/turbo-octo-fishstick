# Copy Starters — Subject Lines, Hooks, Angles per Campaign Type

The calendar produces "copy starters" per scheduled send — 2-3 suggested subject lines, 2-3 SMS drafts, 3-5 ad hooks, a few organic post angles, and 1-2 banner copy options.

These are starters, not final copy — they get the buyer to a working draft in 30 seconds rather than blank-page.

## Why archetype-based starters

Copy starters use the same 5-archetype framework as the rest of the plugin (problem-aware, social-proof, transformation, curiosity-gap, contrarian — shared with skills #5, #6). This keeps the program's voice coherent across campaigns, ads, creator content, and email flows.

When the UGC hook cache (skills #5/#6 shared) has hooks for the products being campaigned, those exact hooks become the starters. When the cache is empty, the skill generates fresh starters using the same framework.

## Ad hook starters per campaign archetype

Match skill #5's framework directly. For each campaign that includes paid ads, the skill suggests 3-5 hooks across archetypes that skill #5 can develop into full ad copy.

### Example: Mother's Day product-launch campaign

```
Problem-aware: Still figuring out Mom's gift?
Social-proof: 3,400 customers gave this for Mother's Day last year
Transformation: The gift that lives on her counter, not in a drawer
Curiosity-gap: One gift Moms keep texting us about
Contrarian: Skip the bouquet this year
```

The calendar's brief flags these hooks per ad-scheduled day. When the buyer runs skill #5 for that campaign, the hooks pre-populate skill #5's archetype slots.

## Organic social starters per campaign archetype

For each organic post scheduled, the skill suggests 2-3 angles:

### Caption-style starters

**Story-led (Instagram-native):**
"Three years ago I was making coffee in a hotel room and I couldn't find one piece of gear that worked. So we made it. Today it's available again..."

**List/educational (TikTok-native):**
"5 things I learned launching [brand]'s second collection: 1) ..."

**Personal (founder voice):**
"OK quick honest one — we almost didn't restock this. Here's why we did..."

**Behind-the-scenes:**
"What goes into one batch of [product]. Sound on..."

**Community / customer-feature:**
"Sending love to [customer name] who's had her [product] for 18 months. Look at this..."

### Visual brief starters

For each post, the visual brief suggests:
- "Overhead lifestyle shot, warm morning light, product visible but not the only subject"
- "BTS shot from the studio — hands working on the product"
- "Customer's home, product in their context"
- "Carousel: 5 slides, each one product detail close-up"

These pair with the caption to form a complete organic-post brief.

## How the starters work with skill chaining

When the UGC hook cache (skills #5/#6 shared) has hooks for the products being campaigned, the skill prefers those over its own generation. This produces coordination:

- Skill #5 (ad creative) writes ad hooks for "ceramic pour over" → stored in cache
- Skill #8 (this calendar) builds a Mother's Day campaign featuring that product → reads cache → suggests the same hooks for the campaign's subject lines and ad rows
- Skill #6 (UGC briefs) is invoked for creator briefs → reads cache → creator scripts match the campaign's voice
- Skill #7 (email flows) builds the Welcome flow → reads cache → subject line of step 1 echoes the campaign's hook

The brand's voice stays unified across every touchpoint. That's the compounding value of the shared cache infrastructure.

---

## Generating starters when caches are empty

When neither the keyword cache nor the UGC hook cache has data for the product/campaign:

1. Generate hooks from the product context + brand voice + campaign type (using the same 5-archetype framework)
2. Note in the brief that running skills #2 and #5/#6 first would improve starter quality through cross-skill coordination
3. Write the generated hooks back to the UGC hooks cache (the same way skill #5 does) so future runs of this skill or other skills benefit

The skill always produces useful starters — caches are enrichment, not requirements.

---

## What the starters are NOT

The copy starters are intentionally NOT final copy. They get the buyer to a draft fast, but final copy benefits from:

- Buyer's voice review (the brand voice profile in config is a starting point; the buyer knows nuances the config doesn't capture)
- Running skill #5 / #7 to develop full versions with character-limit enforcement, compliance checks, and platform-specific tuning
- A/B testing actual sends to learn what works for THIS brand's audience

The .docx brief makes this clear — starters are "use these as a launching point" rather than "send these as-is."
